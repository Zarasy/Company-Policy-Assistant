The rules-based approach retrieves policy text through keyword overlap and does not generate new wording, so its answers are directly traceable to the database. It uses no LLM tokens, although keyword matching can miss relevant policies when users phrase questions differently. The LLM without a vector index receives all 98 policies and can interpret questions more flexibly, but this increases prompt size and token consumption. Its answers must be checked against the underlying policy text because generative models can produce unsupported statements.

The vector-index approach first selects a small number of relevant policies and then asks the LLM to answer using only those excerpts. This reduces the amount of policy text sent to the model and should generally reduce input-token use relative to full-context prompting, though actual time and token results must be measured. I prefer the indexed approach for a larger policy database because it combines targeted retrieval with natural-language answers. However, the current implementation uses TF-IDF rather than semantic embeddings, so it can still miss policies expressed with different vocabulary; a future improvement would use embedding-based retrieval and a systematic evaluation of unsupported answers.
